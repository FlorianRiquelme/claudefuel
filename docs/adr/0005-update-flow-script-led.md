# Update flow: script-led mechanics, release-notes as trust surface

The `/claudefuel.update` skill currently treats every invocation as a first-touch security audit — 130-line `diff -u` of `statusline.sh`, per-step postcondition checkboxes, multiple bash blocks of orchestration narrated turn-by-turn, and an LLM-driven reconcile of the fetched `INSTALL.md`. For the audience that actually invokes it (returning users prompted by the bar's drift signal), the ceremony is theater. The Promptfile model also makes LLM judgment load-bearing on mechanical steps — the v0.3.0 → v0.4.0 session shipped an ad-hoc substitution of `$target_dir/statusline.sh` for the literal `~/.claude/statusline.sh` in `.statusLine.command`, which the model only noticed and reverted afterwards.

We move the update flow off the Promptfile model. The new shape:

1. **`claudefuel` shell script.** A single executable (`~120` lines target) owns all mechanics of forward-reconcile. The `/claudefuel.update` skill becomes a thin launcher: fetch the tagged script, run it, pass output through. **The skill always re-fetches at tag — the local on-disk copy is never trusted as the authoritative executor.** The on-disk copy exists only so `/claudefuel.doctor` can call `claudefuel --inspect` offline; every reconcile drops a fresh copy as part of the bundle. The contract is **forward reconcile**, not "apply now" — the script handles partial-install state implicitly via the same path, and an invocation when nothing has drifted is a clean no-op.
2. **Failure path is dumb-and-bail.** The script has no retry logic, no inline repair, no auto-revert. Any step failure → stop, dump a JSON diagnostic to `cache/claudefuel-update-diagnostic.json`, exit non-zero. The skill catches the non-zero exit and drops to LLM-driven recovery. **Recovery is scoped to the bundle:** the LLM may modify any bundle file and the `.statusLine` key in `settings.json`, and nothing else — no other settings keys, no shell rc files, no files outside `$target_dir/`. This is the same scope boundary `INSTALL.md` already drew; the LLM inherits it instead of re-deriving it. Recovery quality depends on the diagnostic carrying a self-contained desired-state snapshot — so the script embeds the desired-state spec inline in the JSON, making mid-recovery network failures survivable.
3. **Release-body is the trust surface.** Before applying, the script prints the GitHub release body for the target tag and **every interstitial release between installed and target** (a user going v0.4.0 → v0.6.0 sees both v0.5.0 and v0.6.0 bodies). The user confirms `[y/N]`. The body format is contracted in `docs/release-notes.md`: bullet list ≤5 lines, 80 chars each, user-visible changes, optional `Breaking: ...` final line. No code-diff render. No `--diff` flag.
4. **`INSTALL.md` collapses to a paste-line.** The same script that runs on update bootstraps on install. The "Reconcile" section of `INSTALL.md` shrinks to "fetch the `claudefuel` script and run it"; the desired-state contract stays as documentation. The `claudefuel` script joins the bundle as a desired-state entry alongside `statusline.sh`, the five command files, and the `.statusLine` key.

## Relationship to prior ADRs

- **Supersedes the install/update scope of [ADR-0003](0003-stay-bash-conversational-customization.md).** The Promptfile differentiator narrows to `/claudefuel.configure`, which remains the genuine novelty — a conversational config UI inside a running LLM session. Install and update move into the curl-pipe-sh aisle (`claudefuel` is fetched and run; no LLM reconcile). We accept the loss of differentiation on these two paths because it buys substantially better UX for the dominant audience, and because Promptfile-driven mechanics had become a source of LLM-introduced drift rather than the advertised judgment win.
- **Supersedes the primary-check claim of [ADR-0002](0002-upgrade-trust-boundary.md).** The full diff render at confirm-time is removed; it was load-bearing in name but not in practice — 130 lines of bash diff is not auditable by the audience, and the diff is rendered by the same content source it is meant to vet. The secondary LLM audit is also removed (it adds no integrity guarantee once the diff is gone). Tag-pinned fetch remains the integrity boundary it always was. The trust surface contracts to: **tag-pinning + maintainer GitHub account hygiene + release-body discipline.** Signing infrastructure stays rejected on Maintenance ceiling grounds, with the same Sigstore-style escalation path 0002 already named if the threat model changes.

## Consequences

- The CONTEXT.md language for **Promptfile** narrows to `/claudefuel.configure` only. **Reconcile** survives — it is still the canonical operation name — but its operator is now the `claudefuel` script (and, on failure, the LLM scoped to the bundle), not a Promptfile + LLM. The **Drift** and **Drift signal** terms are unchanged; the bar's job is unchanged.
- **`cache/` ownership widens.** It is no longer "statusline.sh-only at runtime" — it is "claudefuel runtime scratch," shared between statusline.sh (`claudefuel-version.json`) and the `claudefuel` script (failure-diagnostic dumps). The INSTALL.md desired-state copy for `cache/` updates accordingly.
- **Release bodies are now user-facing UX, not internal changelog.** A new maintainer obligation: write three to five bullets, user-visible language, before tagging. `docs/release-notes.md` is the contract; consider a GitHub release template to put it in the maintainer's face at release time.
- **Failure-path UX is load-bearing.** The bet is that <5% of invocations hit non-vanilla state and drop to the LLM-recovery path. If that fraction turns out higher, the "less ceremony" claim collapses — the failure path *is* the ceremony, just gated to a smaller cohort. Failure-mode enumeration and a clear diagnostic schema are prerequisites to shipping, not nice-to-haves.
- **The bar's drift signal is a hint, not a gate.** Users may invoke `/claudefuel.update` without seeing it (muscle memory, fresh profile, hand-broken state). The script reconciles regardless. Three observable display modes: `vX.Y.Z — current.`, `vX.Y.Z — current, but bundle is incomplete: ...`, and `vA.B.C → vX.Y.Z` (the upgrade case).
- **Bak files survive.** The script writes `<file>.bak-<TS>` before every write, sharing one UTC `<TS>` per run, identical to current INSTALL.md Step 3. `/claudefuel.rollback` is unchanged. After a successful reconcile the script prunes all but the most recent three sets — a "set" is the group of files sharing one `<TS>`. Three sets is enough for two-hop chain rollback.
- **The on-disk binary is named `claudefuel`, not `claudefuel-update`.** Subcommand-style (`claudefuel update`, `claudefuel inspect`) leaves room for later subcommands without renaming. Skill names (`/claudefuel.update`, `/claudefuel.doctor`, etc.) are unchanged — they remain on the stability contract.
- **Open question deferred to implementation time:** the failure-mode enumeration. The script must decide, per failure class, what `step`/`exit_reason` it dumps. The schema in `docs/plans/update-redesign.md` is a sketch; the real schema lands with the script.
